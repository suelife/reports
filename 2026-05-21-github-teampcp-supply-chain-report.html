2026 年 5 月 18 日，攻擊組織 TeamPCP（又名 Mini Shai-Hulud）向 Visual Studio Code Marketplace 注入惡意版本的 Nx Console 擴展（v18.95.0）。該擴展擁有超過 220 萬裝置安裝量，由合法的 Nrwl 帳號發布，帳號本身已透過前置的 TanStack npm 供應鏈攻擊遭竊取。

惡意版本在上架後僅 18 分鐘即被下架，但短暫窗口已足以竊取至少一名 GitHub 員工的所有開發憑證。攻擊者利用該憑證克隆了 GitHub 約 3,800 個內部私有 repository，涵蓋 Copilot、CodeQL、Dependabot、Codespaces 等核心產品的原始碼及基礎設施配置。

此事件屬於 TeamPCP 自 2025 年 9 月起持續運作的「Mini Shai-Hulud」供應鏈蠕蟲活動之一波，攻擊路徑為 AntV npm → TanStack npm → Nx Console VSCode 擴展 → GitHub 員工機器 → GitHub 內部基礎設施，展現出高度自動化的多層橫向移動能力。

惡意 payload 技術細節

載入機制：payload（498KB 混淆）不直接嵌入 VSIX 擴展檔案，而是在執行時從 nrwl/nx 官方 repo 的 孤立 commit（orphan commit）動態拉取，偽裝成例行 MCP 設定任務。此設計使靜態掃描幾乎無法在上架審查時發現惡意行為。

竊取目標清單：

🎯
GitHub PAT / OAuth Token / SSH Key · npm OIDC Token · AWS Access Key + Secret · 1Password 保管庫 · HashiCorp Vault Token · Kubernetes Config（~/.kube/config） · Anthropic Claude Code 配置（~/.claude/settings.json）

三重外洩通道：HTTPS 直接上傳 / GitHub REST API / DNS tunneling。即使其中一個通道被封鎖，仍可透過其他通道完成外洩，提供攻擊韌性。

Sigstore 濫用：payload 整合 Fulcio 憑證發行和 SLSA provenance 生成，結合竊取的 npm OIDC token，可發布具有合法密碼學簽名的惡意下游套件——使攻擊者的套件看起來是通過驗證的合規構建，繞過基於 Sigstore 的供應鏈完整性驗證。

C2 機制：在 macOS 安裝 Python 後門（cat.py），透過 LaunchAgent 開機自啟。使用 GitHub Search API 以關鍵字 firedalazer 輪詢 C2 指令（RSA-4096 簽名）。資料暫存於公開 GitHub repo，描述欄位為反轉字串 niagA oG eW ereH :duluH-iahS（正讀：Shai-Hulud: Here We Go Again）。

蠕蟲自我擴散：以竊取的 npm token 對受感染帳號管理的其他套件自動發布惡意版本，形成指數級傳播。每個受感染的 CI/CD 環境都是下一波攻擊的起點。

對 GitHub / Microsoft 的直接衝擊

對 Claude Code 用戶的衝擊（首要關注）

⚠️
此為已知第一個明確竊取 Claude Code 配置的供應鏈攻擊。 在 2026-05-18 14:36–14:54 CEST 窗口內開啟任何 VSCode workspace 的開發者，若安裝了 Nx Console，其 ~/.claude/settings.json（含 Anthropic API key 及工作流配置）已可能遭竊取。建議立即輪換 Anthropic API key。

對 npm / 供應鏈生態系的廣泛衝擊

  • Sigstore 信任失效：Sigstore attestation 可用竊取的 OIDC token 偽造，不能作為供應鏈完整性的唯一依據
  • CI/CD 環境全面暴露：受感染的 CI runner 上所有 secrets 均可能遭竊，不限於明確傳遞的環境變數
  • 長尾蠕蟲風險：每個受感染環境都是下一波攻擊的起點，真實影響範圍可能遠超目前已確認的 6,000+ 人

EDR 防護的根本盲區

傳統 EDR 無法偵測 JavaScript / Python 的解釋型擴展，因為它們不是二進制檔案，無簽名驗證機制。VSCode 的 18 分鐘窗口揭示現有 Marketplace 審查流程不足以攔截針對合法發布者帳號的供應鏈攻擊。

⚖️ 爭議與未確認事項

  • 標售金額不一致：各媒體報導 $95,000 或 $50,000，兩個數字均來自暗網貼文引用，未獲獨立確認
  • LAPSUS$ 的實際角色：是主動參與技術攻擊，還是僅作為銷售代理，尚無技術層面的確認證據
  • 客戶資料安全：GitHub 目前表示客戶 repo 未受影響，但調查仍在進行，結論可能更新
  • Windows / Linux 持久化機制：目前公開的 IOC 主要針對 macOS（cat.py + LaunchAgent），其他平台的持久化方式尚未完整揭露

中期防禦強化

  1. VSCode 擴展安裝策略：採用 Aikido 建議的最低上線年限規則（≥ 48 小時），防止剛發布的版本自動安裝；稽核現有已安裝擴展的發布時間異常
  2. npm 版本凍結：CI/CD 環境使用 lockfile（package-lock.json / yarn.lock），禁止非預期版本更新
  3. GitHub API 監控：告警含 firedalazer 等非業務關鍵字的 GitHub Search API 查詢
  4. DNS 異常監控：偵測高頻 DNS 查詢模式（DNS tunneling 特徵），尤其來自開發者工作站
  5. 不應單獨信任 Sigstore：Sigstore attestation 可用竊取的 OIDC token 偽造，供應鏈完整性驗證需配合其他機制
