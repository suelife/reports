VMware vCenter CVE-2026-123890 驗證繞過遭疑似中國關聯 APT 當零時差利用

▲ 需行動

日期：2026/11/19 至 11/20（台北時間）

CVSS 9.8，公告 VMSA-2026-0009（11/20 更新為 .1），沒有暫時解法；請升 9.1.1.0200、9.0.2.0200、8.0 U3m 或 VCF 5.2.5，7.0 無公開修補，延伸支援客戶須洽 Broadcom。Mandiant 稱疑似中國關聯的 ARMORY CASTLE（前 UNC5221）9 月初就以 BONESAW 利用此漏洞，偽造 SAML 建立 SSO 管理員，初始入侵經由 BeyondTrust CVE-2026-102764。虛擬化管理平台一旦失守，整批主機都受影響，應優先處理。

來源support.broadcom.com來源cloud.google.com來源securityweek.com

NGINX nginx2root 修補，HTTP/2 開啟時可遠端執行程式碼，PoC 已公開

▲ 需行動

日期：2026/11/18 至 11/19（台北時間）

F5 修補 CVE-2026-123007、CVE-2026-123633 等 5 個漏洞，其中 123007 影響 1.9.5 到 1.31.8；Wiz 示範免驗證遠端執行程式碼，Xint 串接 Linux SCTP 漏洞逃出容器取得 root；Rapid7、Censys 已公開 PoC，F5 未提及遭利用。F5 稱需 ASLR 被停用或繞過才能執行程式碼，Rapid7 PoC 需約 128 GB 的 HTTP/2 流量。曝險規模 BleepingComputer 引 Censys 約 880 萬（截至 11/19），SecurityWeek 寫約 900 萬。請升 1.30.7／1.31.9 或 Plus 37.0.8.1／37.3.0.1，暫解是關閉 HTTP/2。

來源bleepingcomputer.com來源securityweek.com

Java4Shell：OpenJDK Base64 解碼漏洞可免驗證遠端執行，已見掃描與利用嘗試

▲ 需行動

日期：2026/11/18 至 11/19（台北時間）

CVE-2026-114938 研究者評 CVSS v4 9.2、Oracle 評 8.1，只影響 17.0.6 以後、且在支援 AVX-512 VBMI 的 x86-64 主機（Ice Lake 以後 Xeon、Zen 4 以後）上執行的版本。Oracle 美西 11/17（台北 11/18 05:00）釋出 17.0.21.1、21.0.13.1、25.0.5.1、27.0.1.1 與 8u513-perf，暫解為加上 -XX:-UseBASE64Intrinsics。SecurityWeek 11/19 報導 GreyNoise 記錄 5 個 IP 超過 150 次符合攻擊形狀的請求，WatchTowr 蜜罐看到「java4shell-recon」User-Agent，Previdian 記錄 11/18 至 11/19 共 9 次嘗試，都尚未證實成功入侵。Java 部署面廣，先盤點符合硬體條件的主機能縮小處理範圍。

來源blog.qualys.com來源calif.io來源securityweek.com

▲ 需行動

日期：2026/11/18（台北時間）

ScreenConnect 技術員用戶端 CVE-2026-84869 遭利用；第三方擴充 RMM+ 編為 CVE-2026-127063

▲ 需行動

日期：2026/11/16（台北時間）

Huntress 確認 CVE-2026-84869（CVSS 9.9，9/8 揭露、9/11 列 KEV）遭利用，訪客可在技術員電腦執行檔案：11/12 一名 MSP 技術員電腦約 9 秒內被裝上惡意 ScreenConnect，10/20 起至少 68.8 萬次「run file」請求打向 42 台 MSP 伺服器、來自 29 個 IP。只升級伺服器不夠，技術員用戶端須升到 26.6.5 以上。另外，上週追蹤的第三方擴充 RMM+ 問題已編為 CVE-2026-127063（CVE 頁 11/12 發布，本週才收；CVSS 4.0 評 9.3，CWE-1392 預設憑證），受影響產品是 DataComm RMM+ 擴充，ConnectWise 稱 ScreenConnect 伺服器與用戶端本身不受影響；原因是擴充預設使用靜態 API 金鑰、目前沒有修補版本；ConnectWise 稱約 400 個夥伴環境裝有相關擴充，能處理的已停用，自架者須立即停用。

來源huntress.com來源github.com來源connectwise.com

本週趨勢

  • 修補到被利用的時間差再縮短：GTIG 發現的 exploit_agent 能從修補差異自動寫攻擊碼；Java4Shell、nginx2root 公開數日內就有 PoC 或掃描；Puppet 修補隔天就確認遭利用；Anthropic 也把揭露期限縮到 30 天。
  • 供應鏈與委外仍是主戰場：微軟官方 PyPI 套件遭植入、wfx-loot 以遭盜帳號打 6 萬多個 repo、ScreenConnect 技術員用戶端與第三方擴充、Fireworks 的上游事件波及 Uber。
  • 台灣外洩潮延燒：momo、鳳凰旅遊、台糖、全球商務等相繼公告，領務局案起因也是委外設定錯誤，CYBERBIZ 公告持續增加。

本週行動清單（一般性建議）

  1. 使用 VMware vCenter 者立即升到修補版本；7.0 版沒有公開修補，延伸支援客戶應洽 Broadcom。
  2. 盤點 NGINX 版本並升級；暫時無法升級者先關閉 HTTP/2。
  3. Java 主機依硬體條件盤點 Java4Shell 影響範圍，套用 Oracle 美西 11/17（台北 11/18）釋出的更新或暫解參數。
  4. 檢查 Python 環境是否裝過 agent-framework 1.26.1／1.26.2；裝過者重建環境並輪替所有憑證，相依套件鎖定版本。
  5. MSP 與使用 ScreenConnect 者，把技術員用戶端升到 26.6.5 以上，並停用第三方擴充 RMM+。
  6. 使用 Puppet 者升級到修補版本；GitHub 組織檢查是否有 wfx-docs 分支或可疑 PR，並輪替 Actions secrets。
  7. 收到購物、旅遊平台外洩通知者，留意冒名通知與詐騙訊息。
