📋 Executive Summary

2026 年 5 月 22 日，攻擊者透過劫持 GitHub tag 指向惡意 fork 的手法，在 laravel-lang 三個核心套件中植入含 15 個收集模組的 PHP 憑證竊取器（約 5,900 行），並在幾秒內自動化發布 233 個惡意版本。竊取器針對 AWS 金鑰、17 個 Chromium 瀏覽器密碼、SSH 金鑰、Slack / Discord / Telegram tokens 等高價值憑證，以 AES-256 加密後傳至 C2 flipboxstudio[.]info。Aikido Security 同日偵測並通報，Packagist 隨即下架，但感染窗口期間安裝的開發者環境需立即輪換憑證。

⚠️
攻擊手法繞過標準安全審查：惡意代碼從未出現在官方 repo 的 commit diff 中——攻擊者讓 tag 指向自控 fork 的 commit，通過 Composer 安裝時 autoload 機制自動執行。一般 GitHub 代碼審查無法偵測此類攻擊。

⚙️ 攻擊鏈技術分析

Stage 1：GitHub Tag 劫持（規避 Code Review）

GitHub 允許版本 tag 指向任意 commit，包含 fork 的 commit。攻擊者利用此機制：

  1. 建立惡意 fork，在 src/helpers.php 中插入自執行惡意 block
  2. 將官方套件（laravel-lang/lang 等）的 tag 重新指向惡意 fork 的 commit
  3. 官方 repo 的代碼未改變 → 代碼審查工具不報警
  4. Packagist 驗證 tag 存在 → 視為合法版本 → 分發給 Composer 用戶

Stage 2：Dropper（src/helpers.php 自執行 block）

Composer autoload 機制在安裝時自動 require 所有 PHP 檔案，惡意 src/helpers.php 的自執行 block 因此在套件安裝完成時立即執行：

  1. 指紋識別環境（OS、PHP 版本、環境變數）
  2. 從 flipboxstudio[.]info/payload 抓取 Stage 2 payload（SSL 驗證停用）
  3. 依平台選擇執行方式：Windows 用 VBS、Linux/macOS 用 exec()

Stage 2 Payload：15 模組 PHP 憑證竊取器（~5,900 行）

模組分類具體竊取目標
雲端平台AWS access/secret/session keys、GCP、Azure、DigitalOcean、Heroku、Vercel 憑證
基礎設施Kubernetes configs（kubeconfig）、HashiCorp Vault tokens、Docker credentials
開發者憑證SSH private keys（~/.ssh/）、git configs、.bash_history / .zsh_history
瀏覽器17 個 Chromium 系瀏覽器儲存的密碼（Chrome、Edge、Brave、Opera 等）
通訊Slack workspace tokens、Discord tokens、Telegram session
加密貨幣主流錢包 seed phrases 與 private keys
其他所有 .env 檔案、VPN 配置檔案

外洩方式：所有收集結果以 AES-256 加密後 POST 至 flipboxstudio[.]info/exfil。

感染標記：.laravel_locale/ 目錄（含 MD5 hash 檔案、PHP 腳本、VBS 腳本），可用於主機掃描確認感染。

⚠️ 衝擊評估

嚴重程度：HIGH。竊取器涵蓋範圍極廣，若受感染環境持有 AWS production keys 或 Kubernetes admin credentials，攻擊者可能已取得整個雲端基礎設施的存取權，衝擊遠超開發機器本身。

  • 直接受害者：2026-05-22 窗口期間透過 Composer 安裝 laravel-lang 套件的開發者
  • 潛在二次受害：任何在受感染機器上持有 cloud production access 的組織
  • 跨平台：Windows（VBS）與 Linux/macOS（exec）均受影響，比 Packagist 8 套件攻擊範圍更廣

🛡️ 防禦建議

立即（若曾在 2026-05-22 安裝 laravel-lang 套件）

  1. 感染標記掃描：find ~ -name ".laravel_locale" -type d 2>/dev/null
  2. 封鎖 C2：在防火牆 / DNS 層封鎖 flipboxstudio[.]info
  3. 全面輪換憑證：該機器持有的所有 AWS keys、GitHub PAT、SSH keys、.env 機密；瀏覽器儲存的密碼建議全部更換
  4. 通知相關組織：若機器持有 production cloud 存取權，需通知 security team 並審查 cloud audit logs

中期

  1. Composer 安裝應驗證 tag 指向的 commit 來自官方 repo：目前 Packagist 未強制此驗證，需人工確認或使用 commit hash pinning
  2. 監控異常出站 HTTPS POST：尤其含大型加密 body 的非預期域名請求
  3. CI 環境隔離：套件安裝應在不持有 production credentials 的隔離環境中執行
