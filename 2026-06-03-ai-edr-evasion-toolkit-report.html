威脅行為者用 AI 打造 EDR 繞過工具
Sophos X-Ops 揭露 Cursor + Claude Opus 4.5 多代理工作流，量產後滲透惡意程式

事件日期　2026（開發活動，確切起訖未公開） 公告日期　2026-06-02 報告日期　2026-06-03 受害者　未指名（目標：部署 EDR 之企業環境） 攻擊組織　未公開勒索軟體集團（Sophos CTU 關聯，調查中）
📋 Executive Summary
◆
Sophos X-Ops 揭露一名威脅行為者利用 AI 開發工具加速打造 EDR（端點偵測與回應）繞過框架。 攻擊者以 AI-native IDE Cursor 搭配多個分工 AI 代理（由一個 Claude Opus 4.5 代理擔任協調與規則設定，其餘代理分管 EDR 測試、OPSEC 強化、文件、proxy 壓力測試、VM 佈署），透過「挖掘公開資安研究 → 對照 MITRE ATT&CK → 在實驗室復現」的循環，產出近 80 個模組、涵蓋 70 餘種規避技術。一個中央 Python 工具將 payload 包上加密與規避層，產生自訂 loader，並借用 Cobalt Strike、Sliver 等攻擊框架。
⚠️
關鍵節制（避免過度解讀）：Sophos 明確指出此工作流並非由自主推理的模型驅動，惡意程式本身也沒有內嵌任何 AI——AI 僅用於協調工作流與輔助實驗，每一輪仍倚賴人工審查。此外，攻擊者文件自稱模組「幾乎都能繞過 EDR」，但 Sophos 檢視實際測試資料後並不支持此聲明，部分落差被歸因於 LLM 幻覺。

🎯 攻擊者背景

攻擊者身份未公開具名。Sophos Counter Threat Unit 將此開發活動關聯至已知的勒索軟體佈署與資料竊取行動，但因調查進行中，未揭露具體集團名稱。可從技術跡證歸納的特徵如下：

  • 俄語系跡證：多處腳本與註解以俄文撰寫，指向俄語系操作者，與勒索軟體生態高度重疊。
  • 具工程化能力：建立了含協調、測試、OPSEC、文件、proxy 壓測、VM 佈署等分工的完整開發流程，而非單兵腳本拼湊。
  • 務實的 AI 採用：把 AI 當「加速器」而非「自主攻擊者」——用來壓縮 build／test／refine 循環，但保留人工把關，顯示對 AI 可靠度（幻覺問題）有清楚認知。
  • 規避平台防護的意圖：以「紅隊框架」措辭包裝，Sophos 評估這很可能是為了繞過 Claude 對惡意程式開發的 guardrails。
⚙️ 攻擊鏈技術分析

AI 多代理開發工作流

核心不是「AI 自動寫惡意程式」，而是一套以人為中心、AI 加速的開發流水線。各代理分工如下：

代理角色職責
協調代理（Claude Opus 4.5）負責核心運作、為其他代理設定規則與分派任務
EDR 測試代理對產出的 loader／payload 實測各家 EDR 偵測反應
OPSEC 強化代理降低可偵測性、強化操作安全
文件代理產出技術文件與模組說明（成功率聲明即出自此處，未必反映實測）
Proxy 壓力測試代理測試 C2／代理通道的穩定度與承載
VM 佈署代理部署與管理測試用虛擬機環境
⚠️
循環方法論：挖掘公開資安研究 → 對照 MITRE ATT&CK 技術 → 於實驗室復現 → AI 加速 build／test／refine。Sophos 強調「每一輪仍倚賴人工審查」，AI 並未自主決策。

Payload 產生器與規避層

  • 中央 Python 工具：將 payload 包覆加密與規避層，產生自訂化的 Windows loader（模組化 payload loader generator）。
  • 語言組成：payload 主體多以 Rust 與 Go 撰寫；多個 Python 腳本部分由 AI 生成。
  • 規模：近 80 個模組，涵蓋 70 餘種規避技術。

自動化 Active Directory 探索

Git 儲存庫中含一個「自動化 AD 探索面板」：透過收集已完成任務的觀察結果、從預先定義的動作集合中選擇下一個分支、把工作派發給遠端代理，並在結果回傳時重新評估。Sophos 特別澄清——這是規則式的分支選擇，並非自主推理。

⚠️ 衝擊評估

嚴重程度評為 MEDIUM。本案的意義在於趨勢與門檻，而非單一受害組織的即時重大損害：

  • 降低攻擊工具開發門檻：AI 多代理工作流把「研究 → 復現 → 規避測試」的循環大幅壓縮，使中階攻擊者也能量產自訂 loader——這是真實且結構性的風險。
  • 與真實犯罪行動連動：Sophos CTU 已將其關聯至已知勒索軟體與資料竊取行動，並非純研究性質的概念驗證。
  • 但衝擊被三點節制：(1) 惡意程式本身沒有內嵌 AI、(2) 工作流非自主、需人工把關、(3) 攻擊者自稱的「幾乎都能繞過 EDR」未獲 Sophos 實測支持。
  • 對防守方的真正啟示：AI 改變的是攻擊「速度與規模」，而非繞過防禦的「根本原理」——基本功（修補、MFA、廣布 EDR）仍是有效對策。
💡
結構性觀察：此案與近期「把安全工具變武器」「以紅隊措辭規避 AI 平台 guardrails」的模式一致。值得追蹤的不是「AI 會不會自己寫病毒」，而是AI 平台的濫用防護（guardrails）如何被社會工程式措辭繞過，以及廠商側的偵測與封鎖能力。
⚖️ 爭議與未確認事項
  • EDR 繞過成功率：攻擊者文件自稱成功率持續上升、近乎全面繞過，但 Sophos 檢視實際測試資料並不支持，部分落差歸因於 LLM 幻覺（文件由 AI 代理產出，未必反映實測）。
  • 歸因：具體勒索軟體集團名稱未揭露（調查進行中）；俄語系跡證指向方向但非確證身份。
  • 活動時間範圍：開發活動的確切起訖時間未公開。
  • 「紅隊 vs 惡意」定性：表面包裝為紅隊框架，Sophos 評估為規避 Claude guardrails 的掩護，並判定其實際用於目標環境的隱匿後滲透。
🛡️ 防禦建議
◆
核心訊息：AI 加速的是攻擊產能，不是繞過防禦的物理原理。Sophos 的建議仍是深度防禦的基本功——這些對「AI 量產的規避工具」同樣有效。

Sophos 官方建議

  • 及時修補：維持作業系統與應用程式的修補時效，壓縮初始存取機會。
  • 多因素驗證（MFA）：對所有可遠端存取的帳號啟用 MFA。
  • 採用現代驗證機制：導入 passkeys 等抗釣魚的現代驗證方式。
  • 廣布有效 EDR：在端點全面部署有效的 EDR 解決方案。

針對本案特徵的補強

  • behavior-based 偵測優先：面對快速迭代的自訂 loader，雜湊型偵測易失效，應強化行為與記憶體層偵測。
  • 監控 C2 偽裝流量：留意偽裝成合法 web 請求的 beacon 模式、對 Telegram API 的非預期外連，以及經 Cloudflare Worker 中介的可疑連線。
  • AD 探索告警：對自動化、規則式的 AD 列舉行為（短時間大量 domain trust／remote system discovery）建立告警。
  • EDR tamper protection：啟用防竄改，避免規避模組停用或修改端點代理。
