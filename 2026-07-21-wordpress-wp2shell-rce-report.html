WP2Shell：WordPress 核心 Pre-Auth RCE 漏洞鏈

📋 Executive Summary
◆
未持有登入憑證的攻擊者，可串鏈兩個 WordPress 核心漏洞，在預設安裝的網站上取得完整遠端程式碼執行（RCE）。 該漏洞鏈被命名為 WP2Shell，由 Searchlight Cyber 於 2026-07-17 揭露；WordPress 同日釋出修補。公開 PoC 在揭露後數小時內出現，多家資安公司於 07-20 前確認野外利用。
▲
立即行動：升級至 WordPress 7.0.2 / 6.9.5 / 6.8.6。 全球逾 5 億個網站使用 WordPress，凡運行 6.9.0–6.9.4 或 7.0.0–7.0.1 且未關閉 REST API 者皆在攻擊面上。

⚙️ 攻擊鏈技術分析

攻擊鏈五階段

Step 1
REST 批次路由混淆
serve_batch_request_v1() 讓未驗證請求送達不該存取的處理器
Step 2
繞過權限檢查
請求以未驗證狀態抵達 posts handler
Step 3
SQL 注入抽雜湊
author__not_in 參數注入 WP_Query，導出使用者密碼雜湊
Step 4
偽造管理員
透過 object hydration、oEmbed 快取與巢狀存檔臨時以管理員身份執行
Step 5
RCE / Webshell
取得完整遠端程式碼執行，植入後門

漏洞明細

CVE類型CVSS受影響版本修補版本
CVE-2026-63030 REST API 批次路由混淆（Pre-Auth RCE） 9.8 6.9.0–6.9.4、7.0.0–7.0.1 6.9.5、7.0.2
CVE-2026-60137 WP_Query author__not_in SQL 注入 5.9 6.8.0–6.8.5、6.9.0–6.9.4、7.0.0–7.0.1 6.8.6、6.9.5、7.0.2

兩者單獨風險有限——SQLi 需身分驗證、批次端點缺陷屬邏輯層；但一旦串鏈，路由混淆讓 SQLi 得以在「未驗證」狀態下觸發，門檻從「需帳號」降到「零憑證」，這正是 WP2Shell 被評為關鍵的原因。

💡 核心論點
1
零憑證 + 預設安裝 = 最壞組合。 攻擊不需要任何帳號，也不依賴特定外掛，預設 WordPress 即在攻擊面上，使可利用目標池達到全網規模。
2
AI 正在壓縮「揭露到武器化」的時間窗。 watchTowr 指 PoC 在揭露後數小時內出現，而歷史上通常需 24 小時以上。發現者 Adam Kues 明言「沒有 AI，任何研究者都不可能在 10 小時內找到並完成這條攻擊鏈」。
3
修補已備，時間才是敵人。 官方修補與強制自動更新同日到位，勝負取決於站方多快套用——後門帳號一旦植入，單純升級無法清除既有立足點。

⚖️ 爭議與未確認事項
  • 使用的 AI 模型名稱：觸發文章與 DarkReading 稱 Searchlight Cyber 使用「GPT-5.6 Sol Ultra」。經第一手可查證的僅 Adam Kues「沒有 AI 不可能在 10 小時內完成」的引述（Tenable 引用），具體模型名目前為媒體轉述，尚未見 Searchlight 官方文件直接佐證。
  • 後門帳號與攻擊嘗試數：「數萬次嘗試、逾 100 個後門帳號」源自 watchTowr 的 Attacker Eye 蜜罐網路，屬單一廠商觀測樣本，非全網統計；不同報導對發言人（Jake Knott / Benjamin Harris）歸屬略有出入，但皆為 watchTowr。
  • 影響網站數：「數千萬至上億」為推估。WordPress 全球逾 5 億站為母數，實際易受攻擊者取決於版本分佈與是否關閉 REST API，尚無精確受害統計。
🎯 結論與行動建議
  • 立即升級：將 WordPress 更新至 7.0.2、6.9.5 或 6.8.6；確認 WordPress.org 強制自動更新已生效，勿延後至維護窗口。
  • 假設已被入侵並排查：清點所有管理員帳號、近期新建帳號與外掛，比對建立時間；升級無法移除既存後門，需主動獵捕。
  • 收斂攻擊面：對非必要站台限制或關閉 REST API 批次端點；於 WAF（Cloudflare / FortiGate / F5 等）套用 WP2Shell 簽章作為緩衝。
  • 監控利用跡象：留意針對 REST 批次路由的異常請求、憑證雜湊外洩與 webshell 落地；接入威脅情資持續追蹤變形工具。
  • 將「AI 加速武器化」納入修補 SLA：PoC 已可在數小時內出現，關鍵漏洞的修補窗口應以小時計，而非天。
