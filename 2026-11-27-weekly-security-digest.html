AI 代理找到 MONAI Label 零時差並取得 root，CISA 列 KEV

▲ 需行動

日期：2026/11/24（CISA 美國 11/23 列 KEV；Amazon 揭露為 11/21、修補 10/19 21:37 併入主線（PR #1915）、GHSA 11/18 23:45 公開、0.8.6 於 11/22 09:29 發布，皆早於本週）（台北時間）

Amazon 稱疑中國關聯駭客用開源 AI 滲透框架 Cairn，代理從盤點 API 到能任意寫檔約 11 分鐘，利用的是上傳端點的路徑穿越，再寫入 sitecustomize.py 取得 root；9/8 起約 48 小時攻擊東亞（中國大陸以外）的大學。CVE-2026-133968（CVSS 9.8）依 GHSA 影響 0.8.5 以下、0.8.6 修補，CISA 聯邦期限 11/26。這是 AI 代理自行找到零時差並實際用於攻擊的案例，研究機構使用的醫學影像工具也要納入修補範圍。

微軟 Azure API Management Classic 漏洞遭利用，儲存的 API 憑證被竊

▲ 需行動

日期：2026/11/23（The Register 美東 11/23 07:29 首報；BleepingComputer 美東 11/23 14:42）（台北時間）

微軟 11/18 發現、11/19 封堵，但已外洩的客戶憑證不會自動失效，須由客戶自行輪替；受影響的是 Classic 的 Developer、Basic、Standard、Premium，Consumption 與 v2 不受影響。The Register 報導挪威 NSM 將 Equinor、Skagerak Energi 等能源業遭攻擊連結到此漏洞。雲端服務端已修，不代表客戶端就安全，輪替憑證是客戶自己的責任。

來源bleepingcomputer.com來源theregister.com

本週趨勢

  • AI 代理攻擊從警告變成實例：Cairn 自行找到的 MONAI Label 零時差本週列入 KEV，瑞士 NCSC 首次確認成功的 AI 輔助攻擊，義大利與瑞士也點名多個自主 AI 攻擊工具。
  • 開發者與 SaaS 供應鏈持續出事：1Password、Todoist 都因憑證或 GitHub 帳號遭盜而被入侵，agent-framework 事件疑似牽涉發布管線憑證，Hex.pm 套件庫伺服器也遭利用。
  • 雲端服務端修補不等於客戶安全：Azure APIM、GL.iNet GoodCloud 都是服務端已修，但已外洩的憑證或已中毒的裝置仍要客戶自己處理。
  • 委外與合約結束後的資料殘留：樂桃在合約終止後資料未刪，台灣黑貓、瓦城本週也都是委外系統出事。

本週行動清單（一般性建議）

  1. 使用 Azure API Management Classic 者，輪替儲存在服務中的所有 API 憑證。
  2. 使用 vCenter 者升到同時修補 CVE-2026-123890 與 123903 的版本（例如 8.0 U3m），並限制管理介面存取。
  3. PAN-OS 設備套用 PAN-SA-2026-0015 的 hotfix，管理介面不要對外開放。
  4. Drupal 網站升到 10.6.23、11.3.23 或 11.4.14 並執行 update.php（SA-CORE-2026-019）；暫時無法升級者先封鎖 /core/install.php。
  5. 使用 MONAI Label、Cisco Expressway、Xen Orchestra、NGINX 者確認已套用最新修補；GL.iNet 裝置檢查 IOC 並升級韌體。
  6. 曾使用 Todoist、Hex.pm 或收到委外外洩通知者，更改密碼、重設 2FA，並留意冒名信與簡訊詐騙。
  7. 與委外廠商終止合約時，確認對方已刪除所有資料。
