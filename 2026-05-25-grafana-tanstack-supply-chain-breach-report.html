本報告為 GitHub × TeamPCP（Mini Shai-Hulud）供應鏈攻擊 的延伸個案。Grafana Labs 的入侵根源與 GitHub 遭攻擊同源，均出自 TeamPCP 主導的 TanStack npm 供應鏈蠕蟲攻擊；本報告聚焦 Grafana 作為獨立受害者的事件脈絡、Token 漏輪換的操作失誤，以及勒索拒付的決策。

📋 Executive Summary

2026 年 5 月 11 日，Grafana Labs 偵測到源自 TanStack npm 供應鏈攻擊（TeamPCP 發動）的惡意活動，並立即輪換了大量 GitHub workflow token。然而一個被誤判為未受影響的 workflow token 未被撤銷，攻擊者藉此取得 Grafana GitHub 環境的存取權，下載公開與私有原始碼及部分內部資料。5 月 16 日收到勒索要求後，Grafana Labs 拒絕支付並通報執法機關，於 5 月 22 日公開披露事件。調查確認客戶正式環境與 Grafana Cloud 平台均未受影響。

⚙️ 攻擊鏈技術分析

根本原因：Token 輪換不完整

TeamPCP 的 TanStack npm 供應鏈攻擊（5/11）的惡意 payload 在受害者機器上盜取 GitHub workflow token。Grafana Labs 的應變流程存在一個盲區：

  1. 初始偵測（5/11）：Grafana 偵測到惡意活動並啟動 token 輪換，但評估某個特定 GitHub workflow 為「未受影響」
  2. 誤判導致遺漏：該 workflow 的 token 未被撤銷；事後審查確認此 workflow 實際上已遭到入侵
  3. 持續存取（5/11–5/16）：攻擊者利用該有效 token 在 Grafana GitHub 環境中自由行動，下載程式碼與資料
  4. 勒索施壓（5/16）：攻擊者確認已取得足夠資料後，向 Grafana 發出勒索要求

外洩資料範圍

  • 公開及私有原始碼 repository
  • 含業務運營資訊的內部 GitHub repository
  • 業務聯絡姓名與電子郵件（來自專業往來脈絡）
  • 程式碼未被篡改（下載但無惡意修改）

未受影響範圍

  • 客戶正式環境（生產系統）
  • Grafana Cloud 平台
  • 客戶資料

🛡️ 防禦建議

立即（類似事件應變）

  1. 完整 token 清單驅動的輪換流程：供應鏈事件發生後，不依賴「影響評估」來決定是否輪換——所有 workflow token 一律輪換，無例外
  2. GitHub 稽核日誌審查：事件後立即拉取 git.clone、repository.access 等事件，確認存取範圍
  3. Token 最小權限原則：GitHub workflow token 應限制為 read-only，非必要不授予 contents: write 或 admin 權限

中期

  1. Secret scanning 全面啟用：GitHub Advanced Security / third-party SAST 對 workflow 中的 hardcoded token 進行掃描
  2. 供應鏈事件 runbook：建立供應鏈攻擊的標準應變 runbook，明確規定 token / secret 完整輪換清單，消除「誤判未受影響」的操作空間
  3. 偵測 anomalous clone 行為：監控單一 token 在短時間內大量 git clone private repo 的行為，作為 IOC 之一
